# AlloBench

**AlloBench: Measuring Online Tool Allocation Capability in LLM Agents.**

This repo is a standalone extract of the paper, its harness code, and its result
artifacts, pulled out of a larger multi-project research repo. It contains everything
needed to read the paper, regenerate its figures/tables from the stored run data, and
re-run the benchmark end to end. It deliberately excludes sibling experiments (WoodWorld,
ToolWorld, CREATOR-eval, AIME-disposition, etc.) that lived in the same original repo but
are unrelated to this paper, and excludes superseded artifacts (an earlier SFT fine-tuning
branch, non-canonical precursor runs) that the paper's current text no longer relies on.

## Layout

```
docs/           the paper (.tex), bibliography, and every live design/spec/results doc
figs/           generated paper figures (fig1-fig6, .pdf + .png)
scripts/        the benchmark harness, analysis, plotting, and RL training code
runs/           stored session transcripts / analyses backing the paper's numbers
requirements.txt
tool-investment.tex — the paper itself.
allocation.bib — its bibliography (`\bibliography{allocation}`).
```

### `docs/`
- `tool-investment-paper-review.md` — a self-review of the paper's claims and evidence.
- `paper-structure-outline.md` — the writing scaffold/outline the paper was drafted from.
- `online-tool-investment-plan.md`, `online-tool-investment-working-notes.md`,
  `online-tool-investment-related-work.md` — the project's running design log, working
  notes, and literature map.
- `framing-ladder-spec.md`, `economic-response-surface-spec.md`,
  `gpt-cross-family-r0-r2c-spec.md`, `class-bound-r3-protocol.md`,
  `qwen-tool-transfer-rerun-spec.md`, `rl-ppo-credit-assignment-spec.md`,
  `rl-phase1-results.md` — precise protocol specs and results writeups for each
  experimental arm (the framing ladder R0-R3, the economic sensitivity sweep, the GPT
  cross-family replication, the corrected "class-bound" script-attribution protocol, and
  the Qwen RL case study).
- `box-setup.md` — runbook for standing up the GPU box (Ollama/vLLM) used for the local
  Qwen runs.

> **Not included:** `math_commands.tex` and the `iclr2025_conference` style files that
> `tool-investment.tex` `\input`/`\usepackage`s — these come from an external LaTeX
> template and were never vendored into the source repo. You'll need to add them (or your
> own conference class) to compile.

### `figs/`

The six paper figures (task/core dissociation, framing ladder, economic elasticity,
capability map, RL transfer boundary, reserve-policy shape), each as `.pdf` and `.png`,
generated by `scripts/plot_tool_investment_figures.py`; the `.tex` includes them directly
from `figs/`. Superseded pre-A2 renders are kept in `figs/old/`.

### `scripts/`

- `plot_tool_investment_figures.py` — generates all six main figures from the stored
  `runs/` data and `docs/rl-phase1-results.md`'s published RL values.
- `plot_economic_response_surface.py` — an earlier, narrower economic-surface-only figure
  (`docs/economic-response-surface-spec.md`'s artifact), independent of the consolidated
  script above.
- `tool_investment_benchmark/` — the benchmark harness:
  - `raw_chat.py` — the thin multi-provider chat client (`RawChat`, `provider_for`) the
    whole harness calls into; routes to Anthropic/OpenAI/Ollama/vLLM depending on the
    model string.
  - `urn_common.py`, `stream_builder.py`, `family_kit.py` — shared stream generation
    (latent classes, hot/trap roles, numeric problem families) and urn-episode primitives.
  - `urn_session.py` (R0, abstract keep/pass), `urn_tool_session.py` (R1, same decision via
    tool calls), `claim_solver_session.py` (R2, declarative solver claim, no code),
    `claim_solver_code_session.py` (R2c, code-required claim, correctness not rewarded) —
    the four framing-ladder rungs.
  - `driver.py`, `session_state.py`, `prompts.py` — the R3 full reusable-script harness
    (`write_script`/`run_script`/answer tools) used by `arm_a1_announce.py`.
  - `sandbox_exec.py` — sandboxed script execution and the `has_solve` static-code check
    that `claim_solver_code_session.py` and `session_state.py` depend on.
  - `run_stream_session.py` — shared session runner used by the R0-R2c rungs.
  - `skirental_scorer.py`, `pi_star.py`, `exact_dp.py`, `economic_surface.py` — the
    reference policies and scoring: the exact hindsight net-optimum, the finite-horizon
    Bayesian (Dirichlet) comparator, and the economic (`B`, `K`) response-surface
    machinery.
  - `run_economic_surface.py`, `analyze_economic_surface.py` — driver and analysis for the
    economic sensitivity sweep (Section "Economic Sensitivity").
  - `analyze_gpt_r0_r2c.py` — GPT-family R0/R2c analysis.
  - `test_class_bound_session.py`, `analyze_qwen_class_bound_r3.py` — the corrected
    "class-bound-r3-v1" protocol (attributes write-budget slots to the hidden class they
    execute on) used for the final Qwen script-transfer numbers.
  - `ladder_parity_selftest.py` — a mechanical parity check across the R0-R2c decision
    mechanics.
  - `rl_train.py`, `rl_critic.py`, `rl_reward.py`, `rl_rollout.py`, `rl_urn_pilot.py`,
    `train_lora.py`, `merge_lora.py` — the QLoRA + per-decision PPO training pipeline for
    the Qwen2.5-Coder-14B reward-learning case study.
  - `diag_rl_pilot_rollouts.py` — diagnostic tool for inspecting RL pilot rollouts (the
    idle-tail generation-failure investigation in `rl-phase1-results.md` §4.1).
  - `grading.py` — exact-match/numeric grading helpers shared by the code-emission rungs.

### `runs/`

Stored per-seed session transcripts, configs, and analysis JSON for every arm the paper's
text and appendices actually cite. Naming follows the harness: `urn_*` = R0,
`urn_tool_*` = R1, `claim_solver_*` (no `_code`) = R2, `claim_solver_code_*` = R2c,
`arm_a1_announce_*` = R3, `economic_surface_*` = the (B,K) sweep. Suffixes mark protocol
variants: `_n-announced` = the A2 disclosed-N condition (the paper's primary condition),
`_canonical-structure`/`_mag100` = the Opus R3 arm pinned to the shared canonical stream at
magnitude 100, `_class-bound-v1` = the corrected write-budget-attribution protocol,
`_efr4` = four empty-fence retries (the Qwen idle-tail mitigation), `_vocab-*` = the
lexical-reskin generalization probes, `write-budget-v2` = the GPT write-budget-tracking
fix.

Key directories:
- `urn_haiku`, `arm_a1_announce` — the no-N precursor columns (N=12) still reported
  alongside the A2 columns in Table `tab:haiku2x2`.
- `urn_haiku_n-announced` / `urn_tool_haiku_n-announced` / `claim_solver_haiku_n-announced`
  / `claim_solver_code_haiku_n-announced` / `arm_a1_announce_n-announced` — Haiku's five
  framing-ladder rungs (R0-R3), N=24, the paper's core result.
- `economic_surface_haiku` / `economic_surface_opus` /
  `economic_surface_gpt-5.4-mini-2026-03-17` / `economic_surface_gpt-5.6-sol` /
  `economic_surface_reference` — the (B,K) economic sweep per model, plus the cached
  secondary Bayesian-DP reference.
- `urn_opus_n-announced`,
  `arm_a1_announce_opus_n-announced_canonical-structure_mag100_class-bound-v1` (primary
  R3, magnitude 100), `..._class-bound-v1` (magnitude-1000 completeness check, Appendix
  "Magnitude Sensitivity Check") — Opus's paired R0/R3.
- `arm_a1_announce_gpt-5.4-mini-2026-03-17_n-announced_write-budget-v2_class-bound-v1` /
  `arm_a1_announce_gpt-5.6-sol_n-announced_write-budget-v2_class-bound-v1` — the final GPT
  R3 arms.
- `rl_urn_pilot` — the successful QLoRA+PPO training run/checkpoint for the Qwen case
  study.
- `urn_qwen-rl-base-q8_latest` / `urn_qwen-rl-urn-final_latest` (+ `_vocab-{cauldron,
  quiver,treasure_chest}` reskins, + `urn_tool_*` tool-call-modality variants) — base vs.
  RL-final urn eval, original vocabulary and lexical reskins.
- `claim_solver_code_qwen-rl-base-q8_latest_n-announced_efr4` /
  `claim_solver_code_qwen-rl-urn-final_latest_n-announced_efr4` — Qwen's R2c cells.
- `arm_a1_announce_qwen-rl-base-q8_latest_n-announced_class-bound-v1_efr4` /
  `arm_a1_announce_qwen-rl-urn-final_latest_n-announced_class-bound-v1_efr4` — Qwen's final
  (corrected-protocol) R3 script-transfer cells.
- `vocab3_eval.log` / `vocab3_tool_eval.log` — consolidated logs for the vocabulary-reskin
  probes.

## Reproducing the core results

From the repo root, with `PYTHONPATH=.`:

```bash
PYTHONPATH=. python -u -m scripts.tool_investment_benchmark.urn_session \
  --model haiku --announce-n --seeds $(seq 2000 2023)
PYTHONPATH=. python -u -m scripts.tool_investment_benchmark.urn_tool_session \
  --model haiku --announce-n --seeds $(seq 2000 2023)
PYTHONPATH=. python -u -m scripts.tool_investment_benchmark.claim_solver_session \
  --model haiku --announce-n --seeds $(seq 2000 2023)
PYTHONPATH=. python -u -m scripts.tool_investment_benchmark.claim_solver_code_session \
  --model haiku --announce-n --seeds $(seq 2000 2023)
PYTHONPATH=. python -u -m scripts.tool_investment_benchmark.arm_a1_announce \
  --model haiku --announce-n --full-stream --seeds $(seq 2000 2023) --cap 20.0 --unit-cap 2.0
PYTHONPATH=. python -u -m scripts.tool_investment_benchmark.run_economic_surface \
  --seeds $(seq 2000 2023)
PYTHONPATH=. python -u -m scripts.tool_investment_benchmark.analyze_economic_surface \
  --seeds $(seq 2000 2023) --charges 0 10 20 24
```

then regenerate the figures:

```bash
PYTHONPATH=. python -m scripts.plot_tool_investment_figures
```

See each `docs/*-spec.md` for the full protocol (exact prompts, competence gates,
mechanical-validity checks, and bootstrap procedure) behind its corresponding arm, and
`tool-investment.tex`'s "Commands and Artifact Manifest" appendix for the complete
command set including the Opus, GPT, and Qwen arms.
